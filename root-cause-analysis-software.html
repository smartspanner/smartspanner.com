What is root cause analysis in maintenance?

Root Cause Analysis (RCA) is an investigation into why a maintenance problem happened and what can be changed to reduce the chance of it returning. The repair restores the equipment; the investigation records the underlying cause and the follow-up decision.

For example, replacing a seized bearing gets a conveyor moving. Investigating lubrication records, access and maintenance instructions may explain why that bearing failed. The resulting action might be a procedure change, an inspection or a design improvement, supported by the evidence available.

A useful RCA is clear enough for the next engineer to understand. It does not need a long approval chain or a diagram for every breakdown.

One page, three practical steps

Save an incomplete draft and return when the investigation has progressed.

1. Describe the problem

Explain what happened and its effect on the equipment. Starting from a work order brings through its problem description and asset. You can also create a standalone RCA, with an asset if one is relevant.

2. Record the root cause

Write why the problem occurred and choose a root cause category. Expand the optional 5 Whys section when it helps explain the chain of events. Attach supporting documents if your organisation uses its own analysis paperwork.

3. Define corrective action

Record what should change to prevent recurrence. Create or link one corrective work order for assignment, scheduling and completion through the existing work order system.

Keep the findings with the equipment

The source work order shows its linked RCA records, and the asset record shows RCA history. Engineers can move between the original event, the investigation and corrective work without maintaining a separate action-tracking system.

A 5 Whys example for an equipment breakdown

The 5 Whys method asks successive questions to move from the immediate failure towards its underlying cause. Stop when the explanation is useful and supported by evidence; five completed answers are not compulsory.

  1. Why did the conveyor stop? The drive bearing seized.
  2. Why did the bearing seize? Inspection found inadequate lubrication.
  3. Why was lubrication missed? The new bearing was absent from the lubrication procedure after a machine modification.

In this example, the corrective work should address the missing maintenance instruction as well as the failed bearing. In Smartspanner, you can record up to five question-and-answer pairs and write the final finding in the main root cause field.

This is an illustrative investigation. Check the actual equipment, records and evidence before deciding the cause; a sequence of guesses is not a confirmed finding. For background on the method, see ASQ’s guide to the Five Whys.

Require an RCA after a significant breakdown

Some organisations require an investigation when a breakdown affects operations for a defined period. Smartspanner keeps this automatic requirement separate from the RCA form.

When enabled, completing a breakdown work order checks its stored breakdown downtime. If that operating-hours downtime is X minutes or more, the system creates or reuses an RCA for that work order. The threshold is configurable; its default is 30 minutes and the automatic policy is disabled until configured.

Use business downtime, then investigate after the repair

A breakdown with 45 minutes of stored operating downtime qualifies under a 30-minute policy. A repair spanning two hours overnight with only 20 minutes of stored operating downtime does not. These examples assume the operating schedule and breakdown record are correct.

Completing the breakdown work order does not wait for the RCA. Engineers can restore the equipment and complete the investigation afterwards.

Manual RCA creation remains available from any accessible work order or as a standalone investigation. It is not restricted to jobs that meet the automatic breakdown threshold.

Classify the cause without complicating the investigation

Use six consistent root cause categories to organise the RCA register:

  • Maintenance / Procedure
  • Equipment / Design
  • Operation / Human Factors
  • Materials / Components
  • External / Environment
  • Undetermined

Filter the register by status, asset and root cause category to find relevant investigations. The category supports the written finding; it does not replace it.

RCA categories are different from failure codes

Failure codes classify maintenance events for work order filtering and reporting. An RCA records the problem, its cause and the corrective-action decision. Existing tags and failure codes remain separate from the RCA category.

Three statuses from initial notes to closure

Draft
Investigation started. Save incomplete notes without filling every field.
Open
The problem and root cause are recorded; corrective work or final review remains.
Closed
The investigation is complete and the corrective action has been addressed, or no action is explicitly required.

Closing requires a problem description and root cause, together with corrective-action text or explicit confirmation that no action is necessary. A linked corrective work order must be completed, or cancelled with an explicit no-action decision. Closed investigations can be reopened when findings need to change.

Existing site permissions apply to asset-linked records. A standalone RCA without an asset is shared within the organisation among authorised RCA users.

Root Cause Analysis questions

Do we have to complete all five Whys?

No. The section is optional and accepts up to five ordered questions and answers. Use as many as help explain the cause.

Can we use our own RCA document?

Yes. Attach your organisation's analysis paperwork as supporting documentation. Keep the overall problem, root cause and corrective-action decision in the RCA record so the findings remain easy to find.

Does every RCA need a source work order or an asset?

No. You can start independently and optionally select an asset. Starting from a work order supplies its problem and asset automatically.

Can an RCA stay open after the breakdown is repaired?

Yes. Complete the repair work order when the repair is finished. Save the investigation as Draft or Open and complete it afterwards.

Does this include fishbone diagrams or AI investigations?

No. This release focuses on the problem, root cause, optional 5 Whys and one corrective work order. It does not include fishbone diagrams, fault trees, AI-generated investigations, dedicated RCA analytics or automatic recurrence detection.
